# 帰宅後区分の統合・全日2枚・勝利後の退出（ローカル試験）

## 変更前 → 変更後

- タスク：朝／休日の昼／帰宅後／夜 → 朝／休日の昼／夜。帰宅後のタスクは夜へ移す。平日午後の初期表示も夜へ変更。
- 全日達成：親チェック時の追加チケット1枚 → 2枚。既存の締切・体調スキップ・過去日やり直し対象外の条件は変更しない。
- 勝利画面：ブレイズは「もういちど」、エンダーマンは「そうび／もういちど」しかない → 両方に無料の「かえる」を追加。
- 水の必殺の1発・毎回ランダム・5秒間の試験変更は別資料のとおり維持。

## 移行と報酬の安全策

- `homeSessionRetirement.ts` の純粋な変換を保存読み込み時に適用。子どものセーブごとの `homeRetirement.version` で再移行を防止。今回の確認はメモリ内の仮データのみで、本物のプロフィールやクラウドは操作していない。
- タスクIDの衝突を避けて移す。共有宿題は同じ共有キーを保ち夜の1件へ統合。共有の朝・昼の既存状態は維持し、帰宅での完了・「あとで」は夜へ移す。
- 完了／「あとで」／計測記録／完了時刻を引き継ぐ。元の記録キーも保持する。単発ミッションの受取キーを変えず、受け取り済みを復活させない。
- 保存済み `catchUpDays` も同じID対応で移行。未完了が残る夜の承認は解除する。過去日の承認履歴そのものは自動で書き換えない。
- 旧履歴の帰宅後が未達のままなら、朝を再承認するだけで全日達成にはしない。統合した夜のタスクを完了し、夜の親チェックを受けてから新形式の全日達成へ進む。明示的な「全部できた」操作では現行の全区分を完了する。
- 当日の旧帰宅／夜が承認済みで未受け取りの場合は、承認解除前に元の日付・区分キーで pending に権利を保存。旧日付全体の受領済みキーも尊重する。
- 過去のカレンダー・連続日数は従来の帰宅後を含む判定を維持。新しい日は `homeRetired` により平日2区分、休日3区分で判定する。休日の昼は維持。
- 全日チケットの受領台帳を維持。旧1枚を受け取り済みの日は差額配布しない。未受け取りの日から2枚。起動・移行時の自動配布なし。親チェックの取り消し・再承認・保存再読み込みでも二重配布しない。
- 各区分1枚、4日連続・早ね等の報酬は維持。帰宅後1枚の廃止と全日+1枚の増額により、通常の全達成日総数は平日4枚／休日5枚のまま。
- 勝利の「かえる」は既存 `onClose` のみを呼ぶ。採掘画面へ戻り、チケット・残り行動・戦利品・撃破記録を変更しない。「もういちど」、敗北時の有料再挑戦、エンドラの既存無料退出は維持。
